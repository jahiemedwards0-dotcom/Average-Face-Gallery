# MestizoFaceHarvester

A resumable Wikimedia Commons image-harvesting and **head-view** classification pipeline for the supplied 4,212-record `expanded_manifest.csv`.

The input contains candidate links, not downloaded images. A record counts as downloaded only after the bytes successfully decode with Pillow and a SHA-256 hash is recorded.

## Data rules

- Preserves supplied birthplace, region, country, `gender_qid`, and `gender_label`.
- Does **not** infer gender, ethnicity, ancestry, race, or nationality from appearance.
- Blank supplied gender becomes `unknown` only for folder organization.
- Download/API failures remain `download_failed`; they are never relabeled `rejected_no_face`.
- Exact duplicate bytes are detected by SHA-256. Duplicate manifest rows remain, but repeated image bytes are not stored again.

## Repository layout

- `data/expanded_manifest.csv.gz` — git-friendly compressed copy of the exact 4,212-row input. GitHub Actions expands it to `data/expanded_manifest.csv` before validation and processing.
- `src/collect.py` — orchestrator, test/full selection, resumability, summaries.
- `src/download.py` — serial Wikimedia metadata/download client, validation, hashing, deduplication.
- `src/classify_yunet.py` — YuNet 4-rotation face detection, coarse view estimate, contact sheets.
- `src/package_results.py` — 250–500-record ZIP packaging and durable checkpoint ZIP.
- `.github/workflows/harvest.yml` — GitHub Actions entry point.
- `output/` — cumulative manifests and summaries generated by the workflow.

## Wikimedia behavior

User-Agent shape:

`MestizoFaceHarvester/1.0 (https://github.com/OWNER/REPOSITORY; contact: YOUR_CONTACT)`

The image downloader is serial and defaults to a two-second gap between image requests. It asks the Commons API for approximately 500-pixel thumbnails, honors `Retry-After`, and backs off for HTTP 429/temporary 5xx responses using 60, 120, 300, and 600 second waits. Repeated 429 responses stop the run after the current atomic checkpoint.

No proxy rotation, browser spoofing, robot-policy evasion, or parallel image downloading is implemented.

## 1. Required 50-record test

The `harvest-test` branch is configured so a qualifying push runs **test mode only**. Manual runs are also available under **Actions → Wikimedia face harvest → Run workflow**.

Recommended manual test inputs:

- `mode`: `test`
- `delay_seconds`: `2`
- `repository_url`: the public repository URL
- `wikimedia_contact`: a monitored email address or contact URL

Test mode always selects **exactly 50 records**, distributed round-robin across regions. It never substitutes a smaller core subset.

A successful test creates `output/test_success.json`. Full mode refuses to start without that success marker in the restored checkpoint.

### Inspect contact sheets

After the test, open the `harvest-data` GitHub Release. It contains:

- `front.jpg`
- `three_quarter.jpg`
- `side.jpg`
- `manual_review.jpg`
- cumulative manifests/summaries
- `checkpoint_state.zip`

Zero-count categories still receive a sheet stating that the category contains no images.

## 2. Start or resume the full 4,212-record run

Only after the test succeeds, manually run the workflow with `mode=full`.

Recommended settings:

- `batch_size`: `150`
- `start_index`: `0`
- `delay_seconds`: `2`
- `package_size`: `250`
- `retry_failed`: off unless intentionally retrying failures
- `repository_url`: this repository's public URL
- `wikimedia_contact`: a monitored contact identifier

All 4,212 rows remain in the cumulative manifests. `batch_size` limits only how many new candidate attempts one invocation makes. Completed rows are skipped.

`start_index` is a lower bound, not a replacement subset. Rerunning the workflow resumes forward from the durable checkpoint.

## Checkpoints and cancellation

Candidate progress is written atomically to cumulative CSV manifests. The workflow finalization step creates `packages/checkpoint_state.zip` containing current output state plus uncommitted unique image bytes and organized results, then uploads it to the stable `harvest-data` Release. The next run restores that asset.

Completed global record chunks become immutable assets such as:

- `harvest_0001_0250.zip`
- `harvest_0251_0500.zip`

Cumulative manifests, summaries, contact sheets, and `checkpoint_state.zip` are updated separately.

A hard infrastructure kill that prevents GitHub from executing any `always()` cleanup can still lose the un-uploaded tail of the current runner. Keep `batch_size` conservative.

## Retry only failed records

Set `retry_failed=true`. Successful/terminal rows are skipped. A locally present verified file is reused only when its SHA-256 still matches the recorded hash.

## Local run

The repository stores the input compressed. Expand it first:

```bash
mkdir -p data
gzip -dc data/expanded_manifest.csv.gz > data/expanded_manifest.csv
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
mkdir -p models
curl -fL https://github.com/opencv/opencv_zoo/raw/main/models/face_detection_yunet/face_detection_yunet_2023mar.onnx \
  -o models/face_detection_yunet_2023mar.onnx

export WIKIMEDIA_CONTACT='you@example.com'
export HARVEST_REPOSITORY_URL='https://github.com/OWNER/REPOSITORY'
python -m src.collect --mode test
```

Only after `output/test_success.json` exists:

```bash
python -m src.collect --mode full --batch-size 150 --package-size 250
```

Retry failures only:

```bash
python -m src.collect --mode full --batch-size 150 --retry-failed
```

## Detection and angle classification

YuNet model: `face_detection_yunet_2023mar.onnx`

- Minimum confidence: `0.75`
- Tested rotations: `0°, 90°, 180°, 270°`
- Strongest valid dominant detection is selected using confidence and face area.
- All tested rotations, face count, dominant confidence, dominant bbox, and chosen rotation are recorded.
- No qualifying detection becomes `rejected_no_face`.

The coarse view estimator uses YuNet's five landmarks plus face-box asymmetry and records the method `yunet_5pt_landmark_bbox_asymmetry_v1`.

- `front`: absolute estimated yaw ≤ 15°
- `three_quarter`: > 15° and < 55°
- `side`: ≥ 55°

`manual_review` is used when the dominant face is too small, multiple similarly sized faces are present, landmarks are unstable, or landmark/box pose cues disagree.

Accepted files:

`organized/accepted/{front|three_quarter|side}/{country}/{region}/{gender_label}/`

Manual review:

`organized/manual_review/{country}/{region}/`

## Outputs

The workflow generates:

- `output/download_manifest.csv`
- `output/classification_manifest.csv`
- `output/regional_summary.csv`
- `output/final_summary.json`

`classification_manifest.csv` keeps these outcomes distinct:

- `accepted`
- `manual_review`
- `rejected_no_face`
- `rejected_decode`
- `duplicate_file`
- `download_failed`
- `not_processed`

The regional summary reports candidate count, successful downloads, failures, unique hashes, accepted front/three-quarter/side counts, manual review, rejected-no-face count, and unknown supplied gender count for every country/region pair.

`final_summary.json` explicitly reports candidate records, candidate-level download attempts, verified image records, unique hashes, reused/resumed files, failures, accepted classifications, manual-review cases, rejections, and duplicates.

## Verify final counts

Do not infer completion from the original 4,212 candidate count. Reconcile the manifest and Release packages:

```bash
python - <<'PY'
import json, pandas as pd
m = pd.read_csv('output/classification_manifest.csv', keep_default_na=False)
s = json.load(open('output/final_summary.json'))
print('candidate records:', len(m))
print('verified image records:', m.download_status.isin(['verified','verified_duplicate']).sum())
print('unique hashes:', m.loc[m.sha256 != '', 'sha256'].nunique())
print('remaining not_processed:', (m.classification_status == 'not_processed').sum())
print(json.dumps(s, indent=2))
PY
```

Before calling a full harvest complete, reconcile each Release ZIP's `manifest.csv` ranges with the cumulative classification manifest and verify that no expected record range is missing.
